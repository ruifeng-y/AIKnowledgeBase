# V0.5-A-ADR-001 — Provider Adapter and Registry

## Context

V0.4 used Mock Embedding/Reranker/LLM. V0.5 must support production HTTP providers without breaking frozen Retrieval/RAG contracts or leaking vendor SDKs into Domain/Application.

## Decision

1. **Port + Adapter:** Keep canonical ports (`EmbeddingProviderPort` in `@akb/ai`, `RerankerProviderPort`, `LlmProviderPort` in retrieval/rag domain). Production adapters implement those ports in Infrastructure only.
2. **Provider-specific code stays in Infrastructure:** OpenAI-compatible embedding/LLM HTTP adapters and generic HTTP reranker adapter live under `apps/api/src/infrastructure/providers/`.
3. **Mock / Production isolation:** `providerId=mock` resolves Mock adapters; production config requires endpoint+apiKey (`PROVIDER_NOT_CONFIGURED` otherwise). No silent fallback to Mock in production.
4. **CI stays on Mock:** Deterministic, no secrets, no paid API. Real smoke/integration is opt-in via `PROVIDER_MODE=production` + credentials.
5. **No silent fallback:** Provider failures surface as normalized `PROVIDER_*` errors; RAG/search never auto-switch providers.
6. **No database schema change in V0.5-A:** Consume P1 identity/upsert only.

## Consequences

- New providers = new adapter + registry branch; Application unchanged.
- Reranker HTTP protocol is AKB-defined JSON (not a vendor SDK); swap adapter when a vendor protocol is chosen.
- LLM adapter must not rewrite grounding prompts; Application/Prompt builder owns grounding.
