# V0.5-B-ADR-001 — Provider Runtime Resolution and Observability

## Context

V0.5-A added adapters and a registry but Worker still defaulted `createDefault()` → Mock Embedding. Config was partially read from env in multiple places.

## Decision

1. **Config single source of truth** lives in `packages/config` (`provider-config.ts`). Normalized `EmbeddingProviderConfig` / `RerankerProviderConfig` / `LlmProviderConfig` with validation, defaults, and secret-free `configFingerprint`.
2. **Registry is the only runtime resolution entry** (`ProviderRegistry.resolveEmbedding/Reranker/Llm`). API RetrievalModule and Worker both resolve through this rule (`resolveEmbeddingProvider` shared from `@akb/ai`).
3. **Worker no longer defaults to Mock.** `createFromEnv()` + `resolveEmbeddingProvider()`; production + mock without `EVALUATION_MODE=mock` throws `PROVIDER_NOT_CONFIGURED`.
4. **Mock is explicit** (`providerId=mock`) for CI/tests only.
5. **Health is independent** and capability-validating (config + credential + schema), never a bare ping, never writes business tables.
6. **Metrics stay low-cardinality** (`operation`/`provider`/`model`); no query/chunk/prompt labels.
7. **Logs omit secrets and full prompts/context** by default.
8. **No OTel/Prometheus platform** in this phase; structured logs + lightweight metrics interface only.
9. **No DB schema change.**

## Consequences

- Production runtime cannot silently use Mock.
- Provider config changes require process restart (no hot reload).
- Real provider smoke is opt-in and reports `SKIPPED_PROVIDER_UNAVAILABLE` without credentials.
